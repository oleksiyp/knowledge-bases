# Design a demonstration that leads to useful work

A demonstration should answer three questions: **Is this my problem? Does the output solve it? Can I try it on my own task?** This is an editorial framework derived from comparing the case mechanisms, not a tested conversion formula.

## Build the demonstration around a job

Use a real input, show the relevant transformation, and expose enough of the output for a viewer to evaluate it. State restrictions that affect the buying decision. Use one next step: try a sample, upload an input, or book a narrowly scoped pilot. A long feature tour makes it harder to identify which promise drew the buyer.

Hypothetical examples:

| Product type | Demonstration | Meaningful activation |
|---|---|---|
| Document workflow | A specific question answered with a usable reference | User successfully checks their own document |
| Letter service | A file becomes a correctly addressed order | Paid order accepted for fulfillment |
| Support assistant | A business-specific question answered accurately | Owner installs and tests the assistant |
| Spelling practice | A list becomes an activity the family actually uses | Parent and child complete an exercise |
| Professional images | Representative input and realistic outputs | Buyer obtains a usable delivered image |

These examples describe proposed events, not verified funnels of the named companies.

## Trace the drop-off

If nobody clicks, inspect the audience and promise. If people click but do not start, inspect trust, price, and setup friction. If they start but cannot complete the task, inspect the product. If they complete it but do not pay, investigate the difference between curiosity and willingness to buy. If they pay and disappear, investigate repeat need and delivery quality.

Retain the acquisition creative alongside the cohort record. A message that overpromises can produce strong conversion followed by refunds. A quieter message that attracts suitable customers can be better for the business. Compare the [creator evidence](/cases/jenni.md) and [common metrics](/playbooks/measurement.md).
