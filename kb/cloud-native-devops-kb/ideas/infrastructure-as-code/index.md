# Verdict: mixed

* [Composable control planes for internal APIs](/ideas/infrastructure-as-code/control-plane-composition.md) - Crossplane-style composition can make infrastructure self-service, but the platform team still owns API design and lifecycle behavior.
* [General-purpose languages do not guarantee infrastructure product fit](/ideas/infrastructure-as-code/general-purpose-iac.md) - Language ergonomics are useful, but a programming-language wrapper alone does not establish a sustainable infrastructure tool.

# Verdict: winning

* [Migration-safe infrastructure refactoring](/ideas/infrastructure-as-code/migration-safe-refactoring.md) - Code reuse is most useful when resource identity and traffic movement remain explicit during a migration.
* [Infrastructure as code and the cost of governance changes](/ideas/infrastructure-as-code/open-governance.md) - Declarative infrastructure remained durable, while licensing changes made governance and exit planning part of architecture.
