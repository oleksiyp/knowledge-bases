# Summary
V8 is the most successful language runtime of the period by reach: it runs Chrome (66.4% of worldwide page views in September 2026) and Edge (another 6.0%), and it is the engine inside Node.js, Deno and Cloudflare's workerd, which makes "JavaScript runtime competition" largely a contest of shells around the same engine.[^statcounter][^workerd] Technically the period was a successful re-architecture without a flag day: a non-optimizing baseline compiler (Sparkplug, Chrome 91, 2021), a fast mid-tier optimizer (Maglev, Chrome 117, 2023), and a new CFG-based top-tier backend (Turboshaft) that halved compile time versus the 10-year-old Sea of Nodes design.[^sparkplug][^maglev][^sea-of-nodes] The shadow side is security: Microsoft measured ~45% of V8 CVEs as JIT-related and shipped a JIT-less Edge mode, and Google responded with the in-process V8 Sandbox (on by default from Chrome 123, ~1% overhead).[^sdsm][^sandbox][^thn-sandbox] Verdict: dominant and stable; momentum is now about safety and Wasm, not raw speed.

# What succeeded
- **Cheap tiers beat a smarter top tier.** Sparkplug compiles straight from bytecode without an IR, trading peak speed for near-zero compile cost; Maglev produces "good enough code, fast enough" between Sparkplug and Turbofan.[^sparkplug][^maglev] The V8 team reported Speedometer gains from both, and the approach was copied in spirit by every other engine.
- **Rewriting the top tier incrementally.** Turboshaft replaced Turbofan's backend phase by phase (Chrome 120 onward) and the team says compile time was halved and some phases ran up to 190x faster, with no user-visible flag day.[^holiday-2023][^sea-of-nodes]
- **Embedding.** Because V8 is a library with a stable-ish C++ API and isolates, it became the substrate of Node.js, Deno and workerd. Bun is the only major runtime that chose otherwise (JavaScriptCore), citing startup time and WebKit's monorepo.[^workerd][^bun-jsc]
- **Standards velocity.** Chrome often ships first (WasmGC in Chrome 119; Temporal in Chrome 144), which gives V8 de facto influence over which TC39/Wasm proposals become real.[^wasm-gc-chrome][^temporal-s4]

# What failed or stalled
- **Sea of Nodes.** The IR that defined Turbofan in 2014 was judged too complex ("effect and control chains are hard to understand, leading to many subtle bugs") and too slow to compile; V8 is migrating to CFG IRs.[^sea-of-nodes]
- **JIT as an attack surface.** Microsoft's Edge team found that roughly 45% of V8 CVEs from 2019 on were JIT bugs and that more than half of in-the-wild Chrome exploits abused JIT bugs; Edge shipped a mode that turns the JIT off.[^sdsm] V8's answer (the sandbox) contains rather than eliminates the problem, because the engine stays in C++.[^sandbox]
- **Server-side diversity.** V8's dominance means "runtime competition" (Node vs Deno vs workerd) is mostly about APIs and packaging; engine-level alternatives are rare.

# Lessons
- In a mature engine, the biggest wins came from adding cheap, simple tiers and simplifying the IR, not from a cleverer optimizer.
- A memory-unsafe JIT can be made "safe enough" with sandboxing, but security teams increasingly treat the JIT itself as optional.
- Being the default embeddable engine makes V8 the de facto platform for server JS too, concentrating influence in one vendor.
